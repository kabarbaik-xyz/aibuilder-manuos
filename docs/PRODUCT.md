# Product

## Platform

web

## Stack

User authorized a standalone HTML UI prototype as the development reference. HTML, CSS, and JavaScript for this design artifact; the planned application uses Next.js per the PRD.

## Users

Owners review delivery risk and approve recovery. Supervisors plan dependencies and assignments. Technicians execute tasks and record quantities. Customers track their own orders and acknowledge promise changes.

## Product Purpose

ManuOS coordinates custom make-to-order manufacturing through connected orders, tasks, materials, resources, QC, and history. The UI makes operational status and the next decision clear.

## Positioning

Deterministic engines compute impact and trade-offs, Gemini drafts explanations/proposals, and humans approve consequential changes. Network partners can provide both capacity and materials with explicit consent.

## Operating Context

The design uses the fictional dataset in PRD_MANUOS_PROTOTYPE.md and the existing implementation plan. Desktop/tablet is the primary operation scene, with usable mobile adaptations. The artifact is a local design prototype, not a deployed production system.

## Capabilities and Constraints

Five primary surfaces: Command Center, Orchestrator, Workstation, Customer Portal, and Factory Network. Supporting flows include recovery review, dispatch, history evidence, intake, promise feasibility, passports, and read-only assistant. Interactions in the HTML prototype are simulations; no live Gemini, database, machine telemetry, or production auth.

## Brand Commitments

User supplied three light, blue-accent ManuOS UI references and requested a proper, simple, elegant, usable interface with concise wording. User confirmed balanced density: essential data visible, supporting detail disclosed on demand. Product UI uses English.

## Evidence on Hand

BRD_MANUOS.md, PRD_MANUOS_PROTOTYPE.md, SOFTWARE_ARCHITECTURE_MANUOS.md, IMPLEMENTATION_PLAN_MANUOS_PROTOTYPE.md, and three supplied screenshots. Illustrative operational values are not measured business outcomes. QC-passed progress is78/120=65%; completed quantity82 is distinct.

## Product Principles

- One operational state across all persona views.
- Show the next meaningful action with its consequences.
- Distinguish completed work, verified output, and shipped output.
- Proposals require explicit human approval before application.
- Explain simulated data and capability boundaries honestly.

## Accessibility & Inclusion

Visible focus, keyboard-accessible controls, text plus icons for status, sufficient contrast, responsive desktop/tablet/mobile, and reduced-motion support.
